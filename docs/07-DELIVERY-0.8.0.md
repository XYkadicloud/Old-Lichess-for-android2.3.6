## 一、你提的三件事

### 1. 棋盘太小 → 棋盘现在铺满整个屏宽

**原来为什么小**：界面自上而下是「标题栏 → 对手条 → 棋盘 → 我方条 → 状态条 → 两行按钮」，
光这些非棋盘元素就吃掉约 **224dp**（加上系统状态栏约 25dp），棋盘只剩约 **178dp 高**，
被高度卡死，每个格子只有 **约 16px**。

**改法**：

| 改动 | 效果 |
|---|---|
| 整屏全屏（隐藏系统状态栏） | 省下约 25dp |
| 标题栏 + 对手条 **合并成一行** | 省下约 49dp |
| 我方条压扁（去掉多余内边距） | 省下约 10dp |
| 状态条压到 12sp、单行省略号 | 省下约 7dp |
| 两行按钮 **合并成一行**，高度 44dp → 32dp | 省下约 60dp |

现在非棋盘元素合计约 **99dp**，棋盘可用高度约 **327dp**，而屏宽是 318dp ——
**棋盘变成「宽度受限」**，也就是说它已经铺满整个屏幕宽度，没有浪费。

| | 改前 | 改后 |
|---|---|---|
| 每格边长 | 约 16 px | **约 29 px** |
| 棋盘面积 | 1× | **约 3.2×** |

### 2. 观战 / 玩家名等文字 → 全部压进一行

- 第 1 行：`[观战] 白 luchador2 · 观战 …………………… [12:34]`
  （左边一个绿色小胶囊显示界面标题，中间是对手名，右边是时钟）
- 第 2 行：`黑 XuYL_1a · abc123 ……………………………… [08:21]`
- 第 3 行：`● 轮到你走`（整行状态，颜色随状态变：绿=能走、灰=等对方、红=结束、红闪=将军）

### 3. 选项按钮 → 缩小 + 收进「≡」菜单

按钮统一改成 **32dp 高、12sp 字**的紧凑样式，并且**只占一行**。
基类的规则是：动作不超过 5 个就全平铺；超过就把前 4 个平铺，其余收进 **「≡」** 弹出菜单。

各界面实际排布：

| 界面 | 平铺的按钮 | 「≡」里 |
|---|---|---|
| 观战 | 翻转 / 重连 / 返回 | — |
| 离线双人 | 悔棋 / 翻转 / 新局 / 返回 | — |
| 人机对战 | 提示 / 悔棋 / 新局 / 换边重开 / 返回 | — |
| 谜题训练 | 提示 / 重来 / 下一题 / 类型 / 返回 | — |
| 在线对局 | 和棋 / 认输 / 聊天 / 重新同步 / **≡** | 对手主页、返回 |

> 「返回」现在由基类自动补，子类不用再写。
> 另外这机器有实体返回键，所以即使「返回」进了菜单也不影响操作。

### 4. 棋子图标 → 换成业界通用的 Cburnett 一套

原来的棋子是手画的粗略矢量，在 16px 的格子里糊成一团。现在换成
**Cburnett 棋子**（Wikipedia 上国际象棋条目用的那套，也是 lichess 默认的棋子造型），
授权 CC BY-SA 3.0。

**怎么塞进 APK 的**：没有放图片资源，也没有放 SVG。做法是
`scripts/make_pieces.py` 在**构建期**把 12 个 SVG 解析干净（组样式继承、`transform` 矩阵、
圆弧转贝塞尔、`<circle>` 元素、`fill-rule`、线帽线接），展开成纯绝对坐标，
生成 `app/src/org/lichessold/ui/PieceArt.java`，运行时用 `android.graphics.Path` 重放。

- 12 枚棋子 / 70 个子路径 / **2058 个浮点数**，生成后约 27 KB 源码
- 纯 Java 运算，**不带任何 `.so`**（ARMv6 友好）
- 矢量，格子多大都清晰；APK 体积没有增加
- 白子 = 白底黑描边，黑子 = 黑底（和 Cburnett 原设计一致）

## 二、两台电脑分档（你提的隔离要求）

**核心做法：参数不写死在脚本里，按物理内存自动判定。**

新增 `scripts/machine-profile.sh`：

- 用 `/proc/meminfo` 读真实物理内存（Git Bash 里报的就是 Windows 的实际值），`nproc` 读核数
- ≥12GB → `high`，6~12GB → `mid`，<6GB → `low`
- 输出 `$JVM_BUILD` / `$JVM_SIGN` / `$JVM_DESKTOP` 供构建脚本引用

`scripts/build.config.sh` 已改成 source 它，原来硬编码的 `JVM_LOWMEM` 去掉了。

| | 机器 A（低配机） | 机器 B（本机） |
|---|---|---|
| CPU | Celeron N3060，2 核 | Core 5 120U，10 核 12 线程 |
| 内存 | 4 GB | 16 GB |
| 档位 | `low` | `high` |
| 构建 JVM | `-Xmx320m ... -XX:TieredStopAtLevel=1` | `-Xmx2g -XX:MaxMetaspaceSize=512m`（**启用 C2**） |

这样两头都不会错：低配机不会因为堆太大崩在 `Chunk::new`，
高配机也不会被 `TieredStopAtLevel=1` 白白压着速度。

详见 **`docs/08-MACHINE-PROFILES.md`**（含给 AI 的硬性规则，以及哪些旧文档只适用于机器 A）。

## 五、这一版没做 / 已知限制

1. **棋盘仍然只有点选走子**，没有拖拽。
2. **按钮变小了**：32dp 高（ldpi 下 24px），低于 Android 建议的 48dp 触摸目标。
   这是为了把屏幕让给棋盘的**明确取舍** —— 240×320 的屏幕上二者不可兼得。
   如果实际用起来觉得难点，可以只把 `Theme.compact()` 里的 32 改成 40，一行字的事。
3. **非标准变体**（Chess960 / 疯狂屋 / 原子棋等）依然不支持，棋盘只画标准国际象棋。
4. **桌面测试这一版没有在机器 B 上跑成功**：
   `scripts/test.sh` 会用 `rm -rf build/test-classes` 清理固定输出目录，
   在沙箱环境里被「批量删除保护」拦下（阈值 50 个文件，那个目录有 77 个）。
   这不影响 APK —— 桌面测试覆盖的是 `util/json/net/chess`，这一版**完全没动**这些包，
   而它们在上一个版本（0.7.0）是 109 项全过的。
   要在机器 B 上跑，直接 `bash scripts/test.sh`（不在沙箱里就没有这个限制）。
5. 机器 A 上的构建**没有重新验证**。这一版的 APK 是在机器 B 上出的。
   机器 A 上重新构建前，先 `bash scripts/machine-profile.sh` 确认档位是 `low`。
