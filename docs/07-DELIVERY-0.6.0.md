## 一、这一版改了什么

### 1. 界面全部重做，向 lichess 官网的深色主题对齐

| 项目 | 0.5.0 | 0.6.0 |
|---|---|---|
| 背景色 | 纯黑 `#000000` | lichess 深色 `#161512` |
| 面板色 | 无 | `#262421`（带 1px 描边 + 圆角） |
| 主色 | 无统一主色 | lichess 绿 `#629924` |
| 正文色 | 纯白/灰 | lichess 的 `#bfbdb2`（偏暖的浅灰） |
| 按钮 | Android 2.3 默认的灰色渐变圆角 | **自绘扁平圆角**（`GradientDrawable` + `StateListDrawable`），分主/次/危险三种 |
| 主菜单 | 8 个同款大按钮竖排 | lichess 式**分组列表**：绿色标题栏 + 「下棋 / 学习与观战 / 系统」分组 + 带 `›` 箭头的列表行（带副标题） |
| 对局页 | 一行文字 + 棋盘 + 一行文字 + 按钮 | **玩家条 + 时钟胶囊**：对手条（名字+分数，右侧时钟）/ 棋盘 / 我方条 / 状态条 / 按钮 |
| 棋盘 | 只有格子 + 棋子 | 加**坐标字母数字**、外框、lichess 风格高亮 |

### 2. 棋盘视觉对齐 lichess

- **空格**上画实心圆点，**有子的格**画圆环（不遮挡棋子）—— 这是 lichess 的做法，比一律画圆点清楚得多
- **最近一步**用黄绿半透明高亮（`#9BC700` 41%）
- **选中格**用深绿半透明
- **被将军的王**用红色**径向渐变**（中心红、边缘透明），不是生硬的红方块
- 边线上有坐标 `a-h` / `1-8`，颜色随格子明暗自动反色

### 3. 状态条用符号 + 颜色区分

| 符号 | 颜色 | 含义 |
|---|---|---|
| `●` | 亮绿 | 轮到你走 |
| `○` | 暗灰 | 等待对方 |
| `▲` | 红 | 将军 |
| `≡` | 亮绿 | 三次重复局面 |
| `■` | 红 | 对局已结束 |

时钟胶囊也会跟着变：轮到谁走，谁的时钟胶囊变成亮绿底深字。

## 二、自查修掉的 10 个 Bug

我把全部源码逐文件过了一遍，**查出 4 个会直接毁掉功能体验的硬伤**。详见
[`04-BUGS.md`](04-BUGS.md) 的「自查发现的 Bug」一节。这里只说最严重的三个：

### 🔴 Bug 1：人机对战棋盘方向反了

`AiGameActivity` 里写成 `flipped = !aiIsWhite`。你执白时，**自己的棋子在屏幕上方**，
看上去像对手的棋，人会以为自己执黑。

**修**：改成 `flipped = aiIsWhite`（人类永远在下方）。「换边重开」里的同样错误一并修掉。

### 🔴 Bug 2：在线对局有一半概率棋盘反了、而且走不了子

`gameFull` 的 JSON 里**根本没有 `myColor` 字段** —— 颜色只出现在事件流的 `gameStart`
和 `/api/account/playing` 里。原代码在拿不到颜色时默认成 `"white"`。

后果：从「进行中的对局」列表点进去、或挑战被接受后进入时，
**约一半的对局棋盘方向是反的，而且一步都走不了**（走子权限依赖 `myColor`）。

**修**：新增 `LichessGame.detectMyColor()`，拿 `white.id` / `black.id` 和本地保存的用户名比对。
判断不出来时记一条带完整上下文的警告日志，方便下次真机排错。

> 这条是回去翻 `toolchain/downloads/lichess-openapi.yaml` 的 `GameFullEvent` schema 才确认的。
> **教训：写协议相关代码前必须核对 schema，不能凭印象。**

### 🔴 Bug 3：在线对局时钟以两倍速度掉

每 500ms 从 `shownWtime` 减去"距上次同步的毫秒数"，然后把结果**写回** `shownWtime`。
下一次 tick 又在已经扣过的值上再扣一遍。5+0 的对局会显示成 2.5 分钟。

**修**：拆成 `baseWtime/baseBtime`（服务端权威值，绝不改写）和 `dispWtime/dispBtime`（显示值）。

另外 7 个：棋盘坐标翻转时隐形、重放走子后残留选中高亮、触摸逻辑里有死代码、
引擎排序缓冲共用、谜题页延迟回调没查 Activity 存活、每 500ms 重建 Drawable、
引擎里一个没用到的 1KB 字段。
